## 3. 特記事項

### 3.1 禁域の液体 — 定義だけがある

`MATERIALS` に `forbidden_liquid` として登録され、`ui.slots` が**空配列**になっている。
`getMaterialMax("forbidden_liquid")` は動作するが、入力欄も計算も存在しない。

効果は「主人公のHP +1%/個」で、CLAUDE.md の HP計算式にも
`HP = (100 + VIT × 18) × (1 + 禁域の液体所持数 × 0.01)` と記載済み。
実装されていない理由は、**主人公のHPを表示する画面がサイト内に無い**ため。

### 3.2 ゴッドオブデビルアイ — ✅ 解消済み（`be6c6f4`）

初版時点では、統合計算機と詳細計算機だけが `getCriticalModifier` に渡しており、
ビルドシミュの `bs-devil-eye` は入力欄と保存だけで計算に使われていなかった
（`storage-survey.md` の R-6）。

接続にあたり、**ビルドシミュにはクリティカルON/OFFが存在しなかった**ため
まずトグルを新設した。無条件に適用すると物理ダメージが常にクリティカル前提になり、
既存の逆算結果がすべて変わってしまうため。

- `calcPhysicalKillInfo` / `reversePhysicalAtk` に `criticalModifier` 引数（既定1.0）を追加
- `state.critical` が ON のときだけ `getCriticalModifier(所持数)` を渡す
- デビルアイ欄は ON のときだけ表示する

既定 OFF のため既存の計算結果は変わらない（旧実装と96件一致を確認済み）。

### 3.7 死刑囚の身代わり晩餐 — ✅ 実装済み（`b7daeb0`）

主人公が受けるダメージを1個につき0.09%軽減する。上限1000（パンドラ2000）。

反映先は被ダメージ計算の3箇所。

| ツール | 箇所 | 元の計算 |
|---|---|---|
| 詳細計算機 | 被ダメ（敵物理→主人公） | `damageRangeTotal` |
| 詳細計算機 | 被ダメ（敵魔法→主人公） | `calcMagicDamageRange` |
| ビルドシミュ | `calcReceivedDamage` | `(敵ATK×7 − 自DEF×4) × 属性` |

ビルドシミュだけ別式を使っているが、最終ダメージへの乗算として同じ軽減を適用する。

**軽減率が100%を超える場合はダメージ0で底打ち**する。
パンドラ所持時は2000個で−180%に達するため、約1112個以降は完全無効化になる。

実装上の注意として、`d × (1 − n × 0.0009)` だと浮動小数点誤差で
1000個のとき `floor(10000 × 0.09999…) = 999` と1ずれる。
**1万分率の整数演算** `floor(d × (10000 − n×9) / 10000)` で計算している。

### 3.9 ハデスの兜 — ✅ 実装済み（`0d34dbc`）

ペットの最大レベルを1個につき1上げる。所持上限は1000（パンドラ2000）だが、
**レベル上限は2200で頭打ち**になる。

```
最大レベル = min(2200, 1200 + ハデスの兜の所持数)
```

| 兜の所持数 | 最大Lv |
|---:|---:|
| 0 | 1200 |
| 500 | 1700 |
| 1000 | 2200 |
| 2000（パンドラ） | 2200（頭打ち） |

兜は1000個でレベル上限に到達するため、**パンドラでこの素材の所持上限が
2000になってもレベルへの効果は伸びない**。パンドラの「上限が伸びると効果も
比例して伸びる」原則が当てはまらない唯一の素材。

実装にあたり、ペットステシミュの素材欄を自動生成（`pet-sim:common` スロット）に
切り替えた。それまで手書きだったドラゴン印の手ごね機も同じスロットに載せている。

**Lv1200超のステータス計算は未検証。** `lvBonus` の `Lv>200` の式
`19.9 + (Lv-200) × 1.1` をそのまま延長しているが、実測値と照合していない。

### 3.10 禁域のロック — ✅ 実装済み（`c18bdbc`）

適用先は**装備の通常強化の上限**だった（G強化ではない）。

```
通常強化の上限 = 1100 + 禁域のロック所持数
```

- パンドラの箱を持てば所持上限が2000になり、強化上限は最大3100
- **G強化には影響しない**。G強化の上限300・解禁条件+1100・基準値111はいずれも固定
- 実装は `calc-logic.js` の `getEquipEnhanceMax()`。値の定義は
  `game-data.js` の `LIMITS.equipEnhance`
- 入力欄は `material-ui.js` が生成する。装備DB / ステシミュ / ビルドシミュの3ツール
- 所持数を減らすと、上限を超えた強化値はパンドラと同じ方式で切り詰められる

## 4. 実装するために情報が必要な点

未実装素材を実装する場合に、効果の詳細が不明で計算式を書けないもの。

### 4.1 効果量が不明

| 素材 | 効果テキスト | 不明な点 |
|---|---|---|
| ソラノアエキス | モンスターが生成される時、**少し弱く**計算されて生まれる | 1個あたりの弱体率。対象ステータス（全ステか一部か）。「生成される時」の意味（出現時に固定されるのか、毎回か） |
| ゴールデン小槌 | LUCKに応じてドロップゴールド量が増える | LUCKとの関係式。所持数がどう効くか（所持数×係数×LUKか） |
| 冥府の指輪 | 所持数×10%の確率でアクセサリー経験値の上昇量が増える | 「上昇量が増える」の増加幅。確率は所持数×10%で上限100%か |
| 共有の焚火 | 召喚していないペットにも経験値が0.1%入る*1 | 所持数で0.1%が増えるのか固定か。`*1` の注記の内容 |
| 時空歪曲装置 | 討伐経験のあるボスが1%の確率で複数スポーン*2 | 所持数で確率が上がるのか。「複数」の数。`*2` の注記の内容 |
| 闘技王の遺装 | アリーナのモンスター達のレベル上限が上がる*3 | 1個あたりの上昇量。`*3` の注記の内容 |

初版で挙げた7件のうち**死刑囚の身代わり晩餐は解決**し（0.09%/個・上限1000）、
実装済みになった。残る6件は依然として効果量が不明。

`*1` `*2` `*3` `*4` の注記記号は削除したが（3.8）、**本文の内容は不明のまま**。
共有の焚火・時空歪曲装置・闘技王の遺装の3件は、この注記に
所持数による変化が書かれていた可能性がある。
