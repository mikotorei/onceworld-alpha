# 2026-10-01

## 提案を反映しても Issue が閉じない件を直し、反映せずに閉じた提案を「案」に戻す

提案 #3 を反映しても Issue #2 が閉じず「承認待ち」のまま残った件の修正。調査と修正は miko-hub の手元の Claude Code で行い、同じ変更を miko-hub にも入れた（詳しくは miko-hub の journal/2026-10-01.md）。

### 原因
- GitHub が提案の本文の「Closes #2」を閉じる指示として扱わず、言及としてだけ記録した（公開リポジトリで、作者が Actions のボットだったためと推定）。Issue が閉じなかったので、「完了」に替える仕組み（Issue が閉じた時に動く）も動かなかった。ジョブを3つに分けたことは原因ではない。

### したこと
- `worker-done.yml` に、担当の提案が閉じた時の起点を足した。Issue 番号は作業用の枝の名前（`claude/issue-<番号>-<実行番号>`）から取る。
  - 反映された：Issue を「完了」の扱いで閉じ、「承認待ち」→「完了」。
  - 反映されずに閉じた：「承認待ち」→「案」に戻し、その旨と提案のリンクをコメントする。
- `worker/` を miko-hub と同じ中身に更新した。CLAUDE.md の「担当の職務規定」に完了と却下の動きを1行足した。

### 確かめたこと
- `python -m pytest worker/tests`：38件通過（labels.py が無いので1件は飛ばす）。actionlint：指摘なし。

### 残った課題
- 次の担当の提案の反映で、Issue が自動で閉じて「完了」になることを確かめる。
