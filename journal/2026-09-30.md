# 2026-09-30

## 担当一式を miko-hub から配った（攻略サイトを担当の最初の展開先にする）

ドキュメント「独立に向けた開発の管理」の体制設計タブ「事業への展開」で、最初の展開先をこのリポジトリに決めた。miko-hub の手元の Claude Code から写した。

### したこと
- 指示書の Issue フォーム `.github/ISSUE_TEMPLATE/instruction.yml` を置いた（miko-hub の templates/ の写し。作成時のラベルは「案」）。
- 担当の仕組みを置いた：`.github/workflows/worker.yml`（着手）・`worker-done.yml`（完了）・`worker/`（判定と手順。テストを含む。miko-hub と同じ中身）。
- CLAUDE.md に「担当の職務規定」「作業日誌」「miko-hub での登録」の節を足した。既存の節は変えず、担当として動くときの読み替えを表にした。
- `.gitignore` に `.worker/`・`__pycache__/`・`.pytest_cache/` を足した。

### なぜ
- 公開リポジトリは Actions の実行時間が無料で、miko-hub の月900分の枠を食わない。仕事（HTML・JS の修正、データ更新）が担当向きで、確かめるのもスマホで公開サイトを開くだけで済む。
- 反映した瞬間に利用者の目に触れるので、サイトの仕事はすべて事前承認にした。

### 公開リポジトリのための決まり
- 担当が着手するのは、持ち主が書き、持ち主が「着手可」を付けた Issue だけ（他人が書いた Issue は本文を後から書き換えられるため、「案」に戻してコメントする）。
- 担当に渡すのは指示書のタイトルと本文だけ。コメントは渡さず、担当は GitHub から情報を取りに行かない（コメントは誰でも書けるため）。
- 担当が動くジョブのトークンは読み取りだけ。push・提案・ラベルは担当が動かない別のジョブが行う。
- 上限：同時1件・1日3件・1件40分。月の上限は無い（公開リポジトリのため）。

### 確かめたこと
- `python -m pytest worker/tests`（`pip install -r worker/requirements.txt` のあと）がこのリポジトリでも通ること。
- `hugo --minify` のビルドが、追加したファイルで変わらないこと（`worker/`・`journal/` は Hugo が読まない場所）。

### 残った課題

- 最初の仕事はサイトマップ（sitemap.xml）の作成の予定。
